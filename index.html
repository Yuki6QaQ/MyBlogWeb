制作思路与架构解析

1. 视觉架构：Glassmorphism 风格体系

项目初期，我通过手绘草图确立了“左侧固定侧边栏 + 右侧动态内容区”的双栏布局。为了提升视觉质感，我在全站构建了基于 CSS 变量的 Glassmorphism（毛玻璃） 设计系统。

在 style.css 中定义了 .glass 类，统一使用 backdrop-filter: blur(10px)、半透明背景及细腻边框。这种模块化 CSS 写法确保了全站 UI 的高度一致性。同时利用 content.css 中的 Flexbox 和 Grid 布局，配合媒体查询实现了从桌面端到移动端的无缝切换。

2. 数据驱动开发：解耦 HTML 与 JavaScript

随着作品数量的增加，我引入了数据与视图分离的开发模式。所有个人作品和小组作业的数据被结构化存储在 js/data.js 中，形成了项目的“单一数据源”。

在 js/main.js 中，我编写了渲染函数。程序启动时，JS 遍历数据数组，利用模板字符串动态生成 .work-card 卡片并注入页面。这不仅让主文件保持了极高的可读性，更实现了“修改一处数据，全局自动更新”的高效维护。

3. 交互逻辑与状态管理

为了提升用户体验，我在 js/ui.js 和 js/sidebar.js 中实现了复杂的交互逻辑：

多级联动筛选系统：实现了“父级分类 -> 子级标签”的联动筛选，并根据 data-category 属性过滤显示内容，伴随平滑过渡动画。

无限轮播图与指示器：手动实现了轮播图逻辑，通过控制 transform: translateX 实现平滑切换，并动态生成底部指示器。

滚动侦测与动画：利用 IntersectionObserver API 实现了元素的淡入淡出效果，当用户滚动页面时，卡片和时间轴节点会依次触发可见动画。

4. 模板化详情页与 AI 辅助工程化

在保证主页功能完善后，我设计了通用的项目展示模板 MuBan.html。通过 iframe 隔离技术，确保每个作业的独立 CSS/JS 环境不会污染主博客样式。

在项目收尾阶段，我将分散的模块代码交给 AI 进行深度整合。AI 帮助我优化了 CSS 选择器的优先级，修复了 z-index 层级遮挡问题。这种“人类设计架构 + AI 填充细节”的模式，极大地提升了我的开发效率。

项目总结与反思

1. 技术成长的跨越

通过本次博客系统的从零构建，我完成了从“写静态页面”到“开发动态应用”的思维转变。深刻理解了 CSS 变量在主题管理中的作用，以及 Flexbox/Grid 在复杂布局中的灵活性。特别是在处理侧边栏时间轴伪元素连线时，掌握了相对定位与绝对定位的配合技巧。

在 JS 方面，我掌握了数组方法（map, filter）在数据处理中的应用，学会了如何通过 DOM API 操作页面元素，以及如何通过事件委托优化性能。

2. 难点攻克与解决方案

毛玻璃性能的平衡：初期发现过多的 backdrop-filter 导致滚动卡顿。通过减少模糊半径、使用 will-change 属性提示浏览器优化，最终在视觉效果与性能之间找到了平衡点。

筛选动画的流畅度：在实现作品筛选时，直接隐藏元素显得生硬。我引入了 CSS transition 配合 JS 添加/移除类名，实现了带有透明度变化的平滑过渡效果。

响应式断点的调试：在 responsive.css 中，通过反复测试 992px 和 768px 两个关键断点，解决了移动端导航栏汉堡菜单展开时的层级遮挡问题。

3. 未来展望

目前博客已具备核心功能，但仍有优化空间。计划学习 Vue.js 或 React，将目前的原生 JS 渲染逻辑重构为组件化开发，进一步降低耦合度。

考虑引入简单的 Node.js 后端或 Firebase，实现评论系统、访客统计等动态功能，让博客从“静态展示”走向“双向交互”。同时，针对目前动态渲染内容对搜索引擎不够友好的问题，未来将探索服务端渲染（SSR）或预渲染方案。
